# Problem-Solution-Result

**One-line summary:** A three-beat narrative template — name the Problem, describe the Solution, quantify the Result — used to structure case studies, CV bullets, status updates, and proposal language so that activity becomes evidence of impact.

**When to reach for it:** Consulting case studies, CV / résumé bullets, sales decks, proposal "evidence of past performance" sections, internal status reports, capability narratives, and any communication where the audience needs to evaluate competence based on prior work.

---

## Purpose Of This Thinking Tool

Problem-Solution-Result (PSR) — and its variants PAR, STAR, CAR — is the consulting and corporate world's workhorse narrative shape for *evidence of past competence*. The structure is minimal:

- **Problem** — the situation the protagonist (you, your team, your firm) encountered. Specific, bounded, with stakes.
- **Solution** — what was done. The action taken, the approach, the intervention. The protagonist's contribution.
- **Result** — what happened as a consequence. Quantified where possible; concrete in any case.

The non-obvious operational insight is that **the Result is what most communications skip and what listeners most want to hear.** Activity is easy to describe ("I led a project to redesign the supply chain"); outcomes are harder ("…which reduced delivered cost-per-unit by 17% and cut lead time from 14 days to 6"). When the Result is missing or vague, the narrative collapses into activity reporting, which the audience cannot use as evidence.

The second operational insight is that **the Problem must be sized to the Result.** A small Problem with a big Result reads as exaggeration; a big Problem with a small Result reads as failure. Calibrating the Problem statement to honestly match the Result is the discipline that produces credible evidence rather than implausible claims.

A third insight is the **Solution-attribution discipline.** In consulting and team contexts, the Solution often includes work done by many people. PSR narratives typically use first-person (I / we) but should be honest about the speaker's specific contribution within a larger effort. Over-claiming damages credibility; under-claiming wastes the narrative. Naming the speaker's specific role (lead, contributor, advisor) is the calibration.

## Why Use This Thinking Tool

Three failure modes PSR prevents:

1. **The activity-reporting trap.** Status updates and CV bullets that describe what was *done* without what *resulted* leave the audience to infer competence from activity. They generally don't. PSR forces the Result and surfaces whether the activity actually mattered.
2. **The vague-Result failure.** "Drove significant improvements" or "led major initiative" are non-Results — the audience cannot evaluate them. PSR's discipline is concrete numbers, named stakeholders, specific outcomes. If concrete data isn't available, the next-best Result is a named stakeholder's described reaction; the worst Result is unquantified adjectives.
3. **The mis-sized Problem.** Large protagonists pair Problems too small to justify their stature ("led the team that redesigned the office layout") or too large to plausibly own ("solved customer experience"). PSR forces the Problem to be specific and bounded, which calibrates it to the actual Solution.

For consulting, sales, and any "what have you done?" communication, PSR is the universal template — practiced consultants use it for two-line CV bullets and for ten-page case studies with only volume difference, not structural difference.

## How To Use This Thinking Tool

```
|======|=================================================================================|
| Step |                                     Action                                      |
|======|=================================================================================|
|    1 | Identify the Result first (work backward). What concretely changed? Numbers,     |
|      | stakeholders, decisions, outcomes. The Result anchors everything else.          |
|    2 | Calibrate the Problem to the Result. The Problem must be sized to make the      |
|      | Result plausible — neither bigger (exaggeration) nor smaller (overkill).        |
|    3 | Define the Solution. What action did the protagonist take? Be specific about    |
|      | the intervention, not the activity.                                             |
|    4 | Calibrate attribution. Did "I" do this, did "we," or did the protagonist play   |
|      | a specific role within a larger effort? Match language to truth.                |
|    5 | Draft in PSR order: Problem → Solution → Result. Test that each beat connects   |
|      | causally to the next.                                                           |
|    6 | Compress for the format. CV bullet: 1-2 sentences. Case study: 1-3 paragraphs.  |
|      | Full deck: separate slides per beat. The proportions stay the same.             |
|    7 | Audit: read aloud. Does the audience know exactly what changed and why? If the  |
|      | Result is fuzzy, the narrative fails. If the Problem feels under- or over-sized |
|      | for the Result, recalibrate.                                                    |
|    8 | Stress-test: would a sophisticated audience member ask follow-up questions      |
|      | about the Result? If they wouldn't, the Result is over-asserted; if they need   |
|      | to ask basic questions, the Result is under-specified.                          |
|======|=================================================================================|
```

## The Actual Thinking Tool

```
THE PSR TEMPLATE

   PROBLEM:
       What was the situation? Specific, bounded, with stakes.
       Who was affected? What was at risk?
       Why was it hard?
       _____________________________________________________________

   SOLUTION:
       What did you / we do?
       What was the specific intervention (not the general activity)?
       What was your specific role within any larger effort?
       _____________________________________________________________

   RESULT:
       What changed? (Quantified where possible.)
       Who acknowledged the change? (Named stakeholders, decisions made.)
       Over what timeframe?
       _____________________________________________________________

THE FOUR LEVELS OF RESULT (in decreasing strength)

   STRONGEST: Quantified outcome with a denominator
       "Reduced delivered cost-per-unit by 17% (from $12.40 to $10.30)
       within 9 months across 14 distribution centers."

   STRONG: Quantified outcome without comparative denominator
       "Saved $4.2M annually."

   ACCEPTABLE: Specific stakeholder reaction with named decision
       "The client's CFO adopted the recommendation and the board
       approved the $30M reallocation in December."

   WEAK: Unquantified outcome with named scope
       "The recommendation was adopted across all three regions."

   USE WITH CAUTION: Adjective-only outcome
       "Drove significant improvements in efficiency."

   Default to the strongest form available. If the strongest is not
   accessible (data is confidential, outcome is too recent, etc.),
   say so explicitly rather than substituting weaker language without
   acknowledgment.

THE PROBLEM-RESULT CALIBRATION CHECK

   Hold the Problem and Result side by side. Which of these does your
   pair look like?

   1. Big Problem + Big Result            ←  credible (most common ideal)
   2. Big Problem + Small Result          ←  failure (audience may discount)
   3. Small Problem + Small Result        ←  credible (limited but honest)
   4. Small Problem + Big Result          ←  exaggeration (audience suspicious)

   For (2): consider whether the Problem was too big for the Solution to
   plausibly handle, or whether the Result is under-described. Re-examine.

   For (4): the Problem statement is probably understated. What was
   actually difficult about the Problem? Surface that.

THE ATTRIBUTION-CALIBRATION CHECK

   Three honest framings to choose between:
       "I designed and led..."     — sole or primary owner
       "We designed and led..."    — shared ownership at peer level
       "I contributed to..."       — meaningful but not lead role
       "I supported..."            — assist role; rarely worth highlighting

   Many CV / consulting failures inflate from "contributed" to "led."
   The cost when caught is much higher than the gain when not. Calibrate
   honestly; the best protagonists are credible, not heroic.

CV-BULLET COMPRESSION (the most common short form)

   Template: [Verb] [object/scope] [resulting in / yielding] [Result].

   Examples:
       "Led 8-person team that redesigned APAC supply chain, reducing
        delivered cost-per-unit by 17% over 9 months across 14 DCs."

       "Designed pricing model adopted by sales leadership, increasing
        average deal size 24% within two quarters."

       "Authored board memo that triggered $30M reallocation across
        portfolio."

   Verbs: led, designed, authored, built, negotiated, recovered.
   Avoid: managed, supported, helped, was responsible for, worked on.
   The strong verbs imply ownership; the weak verbs imply distance.

CASE-STUDY EXPANSION (the long form)

   For a full case study, expand each beat:

   PROBLEM (1-3 paragraphs):
       Context, stakes, why it was hard, what made the timing acute.

   SOLUTION (2-5 paragraphs):
       The intervention, the approach, the team's role, the constraints
       worked within, the key decisions made along the way.

   RESULT (1-2 paragraphs):
       What changed, in what dimensions, over what timeframe, validated
       by whom. Include the named stakeholder, the specific decision,
       and the durable outcome.

   The proportions remain ~1 : 2 : 1. Solution gets the most space
   (it's the substance); Problem and Result are scaffolding.
```

> **Operational notes:** Four disciplines. (1) Work backward from the Result. The Result anchors the credibility of the entire narrative; everything else is a scaffold around it. If you cannot articulate a concrete Result, the PSR isn't ready — go find the data, or accept that this isn't your strongest case study. (2) Calibrate Problem to Result. Mis-sized Problems are the second-most-common failure after vague Results — they read as either exaggeration or insignificance. (3) Be honest about attribution. The audience reads "I" and "we" closely in PSR narratives because the framework is specifically about evidence of competence. Over-claiming, when caught, causes disproportionate credibility damage; under-claiming wastes narrative power. Name your specific role. (4) PSR is a structural template, not a literary one. The bullets and paragraphs do not need stylistic flair — they need precision. Resist the urge to "make it sing"; make it specific. Specificity is what makes PSR persuasive.
