# Retrospective Formats

**One-line summary:** A library of lightweight team-reflection formats — Start/Stop/Continue, Sailboat, 4Ls, KALM, and others — designed for regular agile-style retrospectives, with format choice tuned to team maturity, current concerns, and the emotional register the situation calls for.

**When to reach for it:** Agile sprint retrospectives; project-phase closeouts; team rituals (weekly, monthly); after milestones; when a team feels stuck and needs structured reflection; varying format to keep retrospectives fresh; and any context where lightweight repeated reflection beats heavyweight occasional review.

---

## Purpose Of This Thinking Tool

**Retrospective formats** are templates for team reflection. Each format provides:

1. **A simple structure** — usually 3-5 prompts arranged spatially.
2. **A process** — silent generation, sharing, clustering, action.
3. **A specific lens** — different formats surface different aspects (action items vs. emotional register vs. forces vs. principles).

The non-obvious operational insight is that **the format shapes what gets surfaced.** Start/Stop/Continue surfaces concrete actions. Mad/Sad/Glad surfaces emotional register. Sailboat surfaces forces (helping / blocking). 4Ls covers cognitive and emotional aspects. Choosing format deliberately shapes the conversation; defaulting to one format always produces predictable patterns and may miss what's most needed.

A second insight: **rotating formats prevents stagnation.** Teams that always use Start/Stop/Continue eventually produce ritualistic responses. Periodic format change re-engages reflection.

A third insight: **the format is the question bank, not the answer.** Good retrospectives generate specific actions, owners, and follow-up. The format prompts the conversation; it doesn't substitute for the team doing the reflection.

A fourth insight: **the framework distinguishes from heavyweight review.** Retrospectives are lightweight (30-90 minutes), regular (every sprint / cycle), team-internal. They're complementary to deeper post-mortems (after major incidents) or AARs (after specific actions). Different cadences for different purposes.

## Why Use This Thinking Tool

Three failure modes the framework prevents:

1. **The "no reflection" failure.** Teams that don't pause for reflection accumulate untreated issues; performance degrades.
2. **The unstructured-discussion drift.** Open "how did the sprint go?" produces venting or silence. Format provides traction.
3. **The format-fatigue stagnation.** Same format every time produces ritualistic responses. Variation re-engages.

For agile teams, project teams, leadership teams, and any group practicing regular collaborative reflection, having multiple retrospective formats in the toolkit is foundational.

## How To Use This Thinking Tool

```
|======|=================================================================================|
| Step |                                     Action                                      |
|======|=================================================================================|
|    1 | Decide retrospective focus. Action items? Emotional pulse? Forces / blockers?  |
|      | Principles? Format choice follows.                                                |
|    2 | Choose format. Match focus to format from the catalog.                          |
|    3 | Convene team. Set ground rules: psychological safety, focus on improvement.    |
|    4 | Silent generation (5-10 min). Each person writes their items on stickies /     |
|      | digital whiteboard.                                                                |
|    5 | Share and cluster. Items posted; team groups by theme.                          |
|    6 | Discuss and prioritize. Which clusters need action this cycle?                  |
|    7 | Decide actions. Specific items with owners and timelines.                       |
|    8 | Close with appreciation or check-out. Ends the session positively.              |
|======|=================================================================================|
```

## The Actual Thinking Tool

```
THE FORMAT CATALOG

   START / STOP / CONTINUE:
       What should we start doing?
       What should we stop doing?
       What should we continue doing?
       
       Best for: action-oriented teams; concrete outputs.

   SAILBOAT (also Speedboat):
       Wind: what's helping us forward?
       Anchor: what's slowing us down?
       Rocks: risks we should watch for?
       Sun: goal / vision?
       
       Best for: forces-and-blockers focus; visual
       teams; identifying drag.

   4Ls (Liked / Learned / Lacked / Longed for):
       Liked: what went well?
       Learned: what insights emerged?
       Lacked: what was missing?
       Longed for: what do we wish we'd had?
       
       Best for: balanced reflection; covers cognitive
       and emotional.

   KALM (Keep / Add / Less / More):
       Keep: what's working that we should continue?
       Add: what's missing that we should introduce?
       Less: what should we do less of?
       More: what should we do more of?
       
       Best for: continuous-improvement framing.

   MAD / SAD / GLAD:
       Mad: what frustrated us?
       Sad: what disappointed us?
       Glad: what made us happy?
       
       Best for: emotional pulse; teams under stress;
       when feelings need acknowledgment.

   STARFISH:
       Start, Stop, Continue, More of, Less of
       (5 columns)
       
       Best for: nuanced action; "less of" is more
       useful than "stop" in some contexts.

   3-2-1:
       3 things to keep
       2 things to change
       1 question for the team
       
       Best for: time-constrained; focus.

   FUTURESPECTIVE / PRE-MORTEM HYBRID:
       Imagine 3 sprints from now. We're celebrating /
       lamenting. Why?
       
       Best for: forward-looking; complement to
       traditional retrospective.

THE FORMAT-MATCHING DIAGNOSTIC

   Choose format based on:

   TEAM MATURITY:
       Newer team → simpler formats (Start/Stop/Continue)
       Mature team → richer formats (Sailboat, 4Ls)

   CURRENT MOOD:
       Frustrated team → Mad/Sad/Glad acknowledges
       feelings before action
       Optimistic team → KALM emphasizes building on
       what's working
       Stuck team → Sailboat surfaces blockers

   SPRINT CHARACTER:
       Routine sprint → Start/Stop/Continue
       Major release → 4Ls (covers learnings)
       Failed milestone → Mad/Sad/Glad first, then
       action format
       Successful milestone → KALM amplifies what worked

   CADENCE:
       Every 2 weeks → vary formats; routine fatigue
       sets in
       Quarterly → richer format (4Ls, futurespective)

THE FACILITATION DISCIPLINE

   Strong retrospectives have these elements:

   1. PSYCHOLOGICAL SAFETY
        People feel safe surfacing concerns. If
        retrospectives become defensive, learning stops.

   2. STRUCTURE
        Format provides traction. Free discussion
        often degenerates.

   3. SILENT GENERATION FIRST
        Each person writes alone before discussing.
        Prevents groupthink and first-speaker
        dominance.

   4. CLUSTERING
        Group similar items; surface themes.

   5. CONCRETE ACTIONS
        Output is specific items with owners and
        deadlines, not vague aspirations.

   6. FOLLOW-THROUGH
        Last cycle's actions reviewed. If actions never
        complete, retrospectives become theater.

   7. TIME-BOXING
        30-90 minutes typical. Discipline maintains
        respect for time.

THE WORKED EXAMPLE — SAILBOAT RETROSPECTIVE

   Sprint context: shipped a major feature; team
   exhausted; some interpersonal friction emerged.

   Team gathers; uses Sailboat.

   WIND (helping us forward):
       - Pair programming on the hard parts
       - Daily standups stayed short and focused
       - Designer / engineer collaboration was tight

   ANCHOR (slowing us down):
       - QA bottleneck (single person doing it all)
       - Unclear acceptance criteria caused rework
       - Two team members had personality clashes
         affecting code reviews

   ROCKS (risks):
       - Tech debt in the auth module mounting
       - One team member burning out

   SUN (goal):
       - Ship the next feature on time without
         repeating QA bottleneck
       - Address auth tech debt by mid-sprint

   Discussion clusters:
       1. QA capacity (cluster: engineering hires +
       cross-training)
       2. Acceptance criteria (action: PM writes
       acceptance criteria before sprint)
       3. Team dynamics (action: 1:1s with affected
       members; coaching)
       4. Tech debt (action: 20% capacity for auth
       work next sprint)
       5. Burnout (action: rotate person off heaviest
       work for one sprint)

   Each action has owner + deadline; reviewed at next
   retrospective.

THE COMMON FAILURE MODES

   1. SAME FORMAT EVERY TIME
        Ritualistic responses. Recovery: rotate
        formats.

   2. NO ACTIONS
        Discussion without outcomes. Recovery: insist
        on specific actions with owners.

   3. ACTIONS NEVER COMPLETED
        Documented but not done; team becomes cynical.
        Recovery: review prior actions at start of
        each retrospective.

   4. PSYCHOLOGICAL UNSAFETY
        People withhold concerns; surface conversation
        only. Recovery: leadership models
        vulnerability; explicit safety norms.

   5. BLAME-FOCUS
        Retrospective becomes accusation. Recovery:
        ground rules: focus on system / process /
        learning, not on individuals.

   6. SKIPPING REGULARLY
        Pressure to ship leads to skipping
        retrospectives. Recovery: protect the slot;
        the longer-term cost of skipping exceeds the
        sprint-time saved.

   7. WRONG FORMAT FOR CONTEXT
        Action-focused format when team needs to
        process emotion, or vice versa. Recovery:
        match format to current need.

THE OPERATIONAL TEMPLATE

   Sprint / project / cycle: __________________________
   Date / time: _______________________________________
   Format chosen: _____________________________________
   Why this format: ___________________________________

   Silent generation:
       (each person writes items per format prompts)

   Sharing and clustering:
       Cluster 1: ____________________________________
       Cluster 2: ____________________________________
       Cluster 3: ____________________________________

   Prioritized actions:
       Action 1: _________ Owner: ____ Due: _____
       Action 2: _________ Owner: ____ Due: _____
       Action 3: _________ Owner: ____ Due: _____

   Last cycle's actions completed? Y / N
   If N: why not? ______________________________________

   Format note for next time: _________________________
```

> **Operational notes:** Four disciplines. (1) Choose format deliberately. Different formats surface different aspects. Defaulting to one format always misses what other formats would catch. Match format to current need. (2) Silent generation before discussion. The single most important facilitation discipline. Open brainstorm gets dominated by first speakers; private writing surfaces independent items and catches groupthink. (3) Output specific actions. Vague "communicate better" lessons don't drive change. Specific actions with owners and deadlines do. (4) Follow through. Retrospectives whose actions never complete become cynical theater. Reviewing prior actions at the start of each new retrospective is the test of whether the practice is actually working.
