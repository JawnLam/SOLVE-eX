# Kanban Method (Anderson)

**One-line summary:** Visualize work, limit work-in-progress (WIP), manage flow — a pull-based system that exposes bottlenecks and improves throughput.

**When to reach for it:** Software development, service operations, knowledge work; teams whose existing process is push-based and overloaded; gradual evolution toward Lean flow.

## Purpose

Kanban makes work visible on a board (typically columns for stages, cards for work items) and imposes WIP limits per stage. When a stage's WIP is at the limit, no new work can enter — the team must either complete current work or address blockers. The constraint exposes bottlenecks: WIP piles up at the constraint. Throughput improves through addressing constraints rather than pushing more work into the system. Anderson's contribution is the codification for knowledge-work (rather than Toyota's manufacturing) and the principles for evolutionary change.

## How To Use

1) Visualize the existing process as a board with columns for each stage. 2) Set WIP limits per stage. 3) Pull work: a stage takes the next item only when its WIP is below limit. 4) Manage flow — measure throughput, lead time, blockers. 5) Make policies explicit. 6) Improve incrementally.
