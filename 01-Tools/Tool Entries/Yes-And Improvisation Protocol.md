# "Yes-And" Improvisation Protocol

**One-line summary:** A two-word generative rule — accept every offer (yes), build on it (and) — that displaces the default reflexes of blocking, judging, and redirecting; the cumulative effect is collaborative momentum and emergent results no single participant could have produced.

**When to reach for it:** Brainstorming sessions that stall in critique; team meetings where ideas get shot down before they're developed; teaching settings where you want students generating rather than performing-correctness; design or product ideation phases; therapy or coaching where building on the client's frame matters; preparing for high-uncertainty interactions where flexibility is more valuable than prepared scripts.

---

## Purpose Of This Thinking Tool

The non-obvious operational claim of "yes-and": **the default reflex in collaboration is blocking, and the blocking is invisible to the blocker.** Most "let me build on that" moves are actually "let me redirect to my idea" moves; most "interesting, but..." is a no-disguised-as-yes. The "yes-and" rule makes the discipline visible by requiring an explicit acceptance + extension before any modification or critique.

Keith Johnstone's foundational observation (*Impro*, 1979): theatre improv fails when actors block each other's offers. An offer is anything proposed in a scene — a character relationship, a location, an emotion, a fact. Blocking ("no, we're not in a kitchen, we're on a spaceship") collapses the scene because both actors then have to negotiate basic reality rather than build a story. Accepting ("yes, this kitchen-spaceship; and look, the toaster is glowing") creates forward momentum.

The principle generalizes beyond theater because most collaborative contexts have an analogous offer/block dynamic:

- **In brainstorming**: every "but" is a block. Every "no" suppresses the next offer the speaker would have made.
- **In meetings**: status differentials amplify blocking (junior people stop offering after a few blocks).
- **In teaching**: red-pen culture is structured blocking; the student stops offering.
- **In design**: "we tried that" is the most common block.

The protocol's mechanism: **"yes" forces acceptance of the offer's underlying contribution before any modification.** "And" forces a build that *increases* the scene's information, not just preserving it.

A second insight: **"yes-and" is not "yes to everything literally."** A medical context cannot "yes-and" a patient's harmful idea. The discipline is about the collaborative-generative phase, not the evaluative-decision phase. The phases must be separated: yes-and during ideation, critique during evaluation. Mixing them collapses both.

## Why Use This Thinking Tool

Three failure modes the protocol prevents:

1. **Premature critique.** Killing ideas before they're built out. Most ideas need 3-5 builds before their value can be assessed; blocking at build 1 forecloses the assessment.
2. **Status-cascade silencing.** When senior people block, junior people stop offering. The team's idea-density collapses. Yes-and creates symmetry — the senior person must also build on the junior offer.
3. **Disguised blocking.** "Yes, but" / "interesting, but" / "I'd love to but" — all are blocks dressed as yeses. The protocol's explicit "yes + and" structure surfaces the disguise.

This tool's evidence base is theatrical (the improv tradition since the 1960s), educational (improv in adult learning since the 1980s), and corporate (improv-for-leadership since the 2000s). Empirical research is thinner than the practical literature; the strong claim is that the rule works *operationally* in collaborative contexts.

## How To Use This Thinking Tool

```
|======|=================================================================================|
| Step |                                     Action                                      |
|======|=================================================================================|
|  1   | Frame the session as "yes-and only." All participants commit explicitly.        |
|      | Critique phase will happen later, separately.                                   |
|  2   | Set the prompt or starting offer. ("What if we redesigned the onboarding?")    |
|  3   | First participant offers an idea. Doesn't have to be good — just an offer.     |
|  4   | Next participant: "Yes, and ___" — accepts the offer and adds something.       |
|      | The build must INCREASE information; "yes, and that's interesting" doesn't    |
|      | qualify.                                                                        |
|  5   | Continue around. Each "yes-and" builds on the immediate prior, not on a        |
|      | bypassed earlier idea.                                                          |
|  6   | If anyone catches themselves about to block, stop, name it ("I was about to    |
|      | block — let me try a 'yes-and' instead"), and re-attempt.                       |
|  7   | After the generative round, transition explicitly to a critique round. Now     |
|      | "but" is allowed. Both phases get their work done.                              |
|======|=================================================================================|
```

## The Actual Thinking Tool

```
"Yes-And" Session Protocol

PHASE 1 — GENERATIVE (set time-bounded, e.g., 15-30 min)
   Rule: every response begins with "Yes, and..." — no exceptions.

   Starting offer: ________________________________________

   Round 1:  Person A — yes-and: ____________________________
   Round 2:  Person B — yes-and: ____________________________
   Round 3:  Person C — yes-and: ____________________________
   ...

   BLOCKING TELLS (catch yourself or others):
   "Yes, but..."
   "Interesting, but..."
   "We tried that..."
   "That won't work because..."
   "Have you considered..."  (redirect)
   "Building on that..." followed by completely different idea  (disguised block)

   When caught: name it, reset, re-attempt.

PHASE 2 — CRITIQUE (explicit transition; bounded)
   Now "but" is allowed.
   Evaluate the build-outs from Phase 1.
   Pick which to develop further; discard others.

QUALITY OF SESSION:
   Information added per round: high / medium / low
   Status cascade (junior people offering as much as senior?): yes / no
   Did emergent results appear that no individual would have proposed?
   ____________________________________________________
```

> **Operational notes:** (1) **"Yes-and" is not "yes to anything actually proposed in life."** It is a rule for the generative phase. Decision phases require critique. Confusing the two collapses both. (2) **High-status participants must commit hardest.** If the leader blocks even once, the protocol collapses for the room. Practice the discipline before deploying it in a real meeting. (3) **Some "yes-ands" are weak builds** — "yes, and that's a great idea" doesn't add information. Coach toward concrete additions. (4) **Cultural context.** "Yes-and" works in low-power-distance cultures more easily; in high-power-distance contexts, the rule needs more setup and modeling. (5) **For solo brainstorming**, use the rule as an internal discipline — every idea you write down gets a "and" extension before you evaluate it. Same effect, single-player.
