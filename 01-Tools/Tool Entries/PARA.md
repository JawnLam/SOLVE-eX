# PARA

**One-line summary:** Tiago Forte's organizing system for personal knowledge and files: Projects (active work with deadline), Areas (ongoing responsibilities), Resources (topics of interest), Archives (inactive items) — organizing by actionability rather than topic.

**When to reach for it:** Personal information / file management; organizing notes, documents, and research materials; replacing topic-based folder structures that don't serve productivity; setting up a personal knowledge management system; and any context where "where does this go?" for a new piece of information matters and topic-categorization isn't enough.

---

## Purpose Of This Thinking Tool

**PARA** organizes information by actionability. The four categories:

1. **Projects** — short-term efforts with defined goals and deadlines. "Launch the Q4 marketing campaign," "Write the strategy memo," "Plan the family vacation."
2. **Areas** — ongoing spheres of responsibility without specific deadline. "Health," "Marketing function," "Personal finance," "Apartment maintenance."
3. **Resources** — topics or interests not currently active in projects or areas. "Photography," "Cognitive science," "Italy travel."
4. **Archives** — inactive items moved out of any of the above. Completed projects; deprecated areas; resources no longer of interest.

The non-obvious operational insight is that **actionability is a more useful organizing axis than topic.** Topic-based folder structures (e.g., "Marketing/Customer Research/Surveys/2025") look organized but make retrieval hard ("where did I save that survey result?"). Actionability-based organization (Projects → Active marketing campaign → Survey results) connects information to use; retrieval follows from the activity that needs it.

A second insight: **the framework lives across tools and platforms.** PARA isn't a tool; it's an organizing principle. The same four-category structure applies in Notion, Google Drive, Apple Notes, file system, email folders. Cross-tool consistency is part of the value.

A third insight: **the framework solves the "where does this go?" problem.** When new information arrives, ask: which Project does this serve? Which Area? If neither, is it a Resource for future use? File accordingly.

A fourth insight: **the Archives category is essential.** Without explicit archiving, completed projects and deprecated areas clutter active categories. The discipline of moving inactive items to Archives keeps active categories useful.

## Why Use This Thinking Tool

Three failure modes the framework prevents:

1. **The "topic-based filing breaks down" problem.** Topic categories proliferate; same information gets filed under multiple; retrieval depends on guessing where you put it.
2. **The "scattered tools" disorganization.** Information in many places (notes app, Drive, email, Slack) without consistent structure.
3. **The "active-vs-inactive confusion."** Active projects and dormant interests mixed in same categories; active work harder to surface.

For knowledge workers, students, anyone managing personal information across multiple tools, PARA is foundational organization.

## How To Use This Thinking Tool

```
|======|=================================================================================|
| Step |                                     Action                                      |
|======|=================================================================================|
|    1 | Set up four top-level folders / categories: Projects, Areas, Resources,         |
|      | Archives.                                                                         |
|    2 | List your current Projects (defined goal + deadline). Each gets a folder.       |
|    3 | List your Areas (ongoing responsibilities). Each gets a folder.                 |
|    4 | Move existing notes / files into appropriate Projects or Areas based on use.    |
|    5 | Topics not connected to current Projects or Areas → Resources.                  |
|    6 | Inactive / completed items → Archives.                                            |
|    7 | Apply the structure across tools (notes, files, Drive, etc.).                    |
|    8 | Periodically review: complete projects move to Archives; new projects added;   |
|      | resources promoted to projects when they become active.                          |
|======|=================================================================================|
```

## The Actual Thinking Tool

```
THE FOUR CATEGORIES

   PROJECTS:
       Active work with goal + deadline
       Examples:
           "Q4 marketing campaign launch — Dec 1"
           "Strategy memo for board — Nov 15"
           "Italy vacation planning — depart Jan 15"
       Lifespan: weeks to months
       Contains: notes, drafts, references, files
       relevant to this specific effort

   AREAS:
       Ongoing responsibilities, no deadline
       Examples:
           "Health"
           "Personal finance"
           "Marketing function" (if your role)
           "Apartment maintenance"
       Lifespan: indefinite
       Contains: standards, recurring info, ongoing
       reference

   RESOURCES:
       Topics or interests not currently active
       Examples:
           "Photography"
           "Wine"
           "Cognitive science"
           "Italian language"
       Lifespan: until promoted to project / area
       Contains: collected materials, articles, ideas

   ARCHIVES:
       Inactive items from any other category
       Examples:
           "2024 Q3 marketing campaign — completed"
           "Apartment in Brooklyn — moved out"
           "Photography — abandoned"
       Lifespan: forever (don't delete; archive)

THE ASSIGNMENT RULES

   New information → which category?

   Q1: Is there a current Project this serves?
       Yes → Project folder.
       No → Q2.

   Q2: Is there a current Area this is part of?
       Yes → Area folder.
       No → Q3.

   Q3: Is this a topic of interest for future use?
       Yes → Resource folder.
       No → Archive (or delete if not worth keeping).

   The decision tree handles routing in seconds.

THE PROJECT-vs-AREA DISTINCTION

   Project: definite goal + deadline.
       "Launch X by Y date."
       Has a clear "done" state.

   Area: ongoing responsibility.
       "Maintain healthy diet."
       No "done" state; continuous.

   Common confusion: "improve my health" — is this a
   project or area?
       As stated: too vague. If "lose 20 lbs by July
       1," it's a project. Otherwise, it's the Area
       "Health."
       
       Areas spawn projects ("ongoing health" → "lose
       20 lbs project"). Projects complete; areas
       continue.

THE WORKED EXAMPLE — KNOWLEDGE WORKER

   PROJECTS:
       Q4 sales planning (deadline: Nov 30)
       Hiring senior PM (deadline: Dec 15)
       Italy trip (deadline: Jan 15)
       Annual review prep (deadline: Dec 1)

   AREAS:
       Sales function (ongoing role)
       Career development
       Personal finance
       Family / household
       Health

   RESOURCES:
       Cognitive science
       Cooking
       Photography
       Travel inspiration
       Strategy frameworks

   ARCHIVES:
       Q3 sales planning (completed)
       Old apartment (moved out)
       Past job materials (left company)
       Project from previous role

   Each tool (Notion, Drive, etc.) has the same four
   top-level structure. Cross-tool consistency.

THE PERIODIC REVIEW DISCIPLINE

   PARA breaks down without periodic review:

   WEEKLY:
       Add new projects
       Move completed projects to Archives
       Surface stalled projects

   MONTHLY:
       Review Areas: still relevant?
       Promote Resources to Projects when activated

   QUARTERLY:
       Major Archive cleanup
       Re-baseline structure

   Without review, structure drifts: completed
   projects clutter active; new initiatives don't
   get added; Resources accumulate without review.

THE COMMON FAILURE MODES

   1. NO SETUP
        Top-level structure not established. Recovery:
        create the four folders.

   2. TOPIC-BASED RELAPSE
        Falling back to "Marketing/Research/Customer/..."
        Recovery: enforce PARA top-level.

   3. NO ARCHIVING
        Completed projects clutter active. Recovery:
        regular archive sweeps.

   4. EVERYTHING-IS-A-PROJECT
        Areas labeled as projects without deadlines.
        Recovery: distinguish; areas don't have
        deadlines.

   5. CROSS-TOOL INCONSISTENCY
        PARA in Notion; topic-folders in Drive.
        Recovery: same four categories everywhere.

   6. NO PERIODIC REVIEW
        Structure drifts. Recovery: weekly / monthly
        review.

   7. PROJECTS WITHOUT GOALS
        Vague "Marketing" listed as project. Recovery:
        define goal + deadline.

THE OPERATIONAL TEMPLATE

   Setup:
       PROJECTS: ___________________________________
       AREAS: ______________________________________
       RESOURCES: __________________________________
       ARCHIVES: ___________________________________

   New information assignment:
       Item: _________________________________________
       Active Project? Y / N. If Y: ________________
       Active Area? Y / N. If Y: ___________________
       Resource? Y / N. If Y: ______________________
       Archive? Y / N

   Cross-tool consistency:
       Notes app: PARA top-level? Y / N
       Drive: PARA top-level? Y / N
       Other tools: ________________________________

   Review schedule:
       Weekly: completed projects, new projects
       Monthly: areas, resource activation
       Quarterly: major cleanup

   Active project count: ______ (recommend: 5-10 max)
   Active area count: _______ (recommend: 5-10)
```

> **Operational notes:** Four disciplines. (1) Organize by actionability, not topic. The default instinct is topic-based filing; PARA's discipline is connecting information to current use. The shift is uncomfortable initially but produces faster retrieval. (2) Distinguish projects from areas. Projects have deadlines and "done" states; areas are ongoing. Conflating them produces vagueness. (3) Apply across tools. PARA's value is in cross-tool consistency. The same four-category structure in notes, files, and platforms enables one mental model. (4) Review periodically. Structure drifts without review — completed projects clutter active, new initiatives don't get added, Resources accumulate without curation. Weekly / monthly / quarterly reviews maintain the system.
