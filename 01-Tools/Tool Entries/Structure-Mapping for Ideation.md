# Structure-Mapping for Ideation (Gentner)

**One-line summary:** A protocol for analogical ideation that maps *relational structure* (not surface similarity) from a well-understood source domain onto a less-understood target — the borrowed structure scaffolds thinking and surfaces ideas that domain-internal reasoning misses.

**When to reach for it:** Stuck on a problem where the domain's own vocabulary is producing only canonical solutions; teaching a complex topic and reaching for the right analogy; product design that benefits from cross-domain transfer; theory-building where another field's structure illuminates yours.

---

## Purpose Of This Thinking Tool

Dedre Gentner's *Structure-Mapping Theory* (1983) is the cognitive science account of how analogy works productively. Her central distinction:

- **Surface similarity** — two domains share object-level attributes. Solar system and atom both "have a center and orbits." This is what most casual analogies notice.
- **Structural similarity** — two domains share relational patterns. Solar system and atom both have *gravity-like attraction between center and periphery, with the relative masses determining orbital characteristics*. The relations transfer; the surface attributes don't have to.

The non-obvious operational insight: **good analogical ideation maps relational structure, not surface attributes.** Bohr's atom model worked because it borrowed the orbital *structure* of the solar system; it would have failed if Bohr had insisted that electrons must literally be small planets. The structure transfers; the attributes are domain-local.

Gentner's mapping procedure:

1. **Select source domain.** Pick a well-understood domain with rich relational structure.
2. **List the source's relations.** Not just objects — relations between objects. "A attracts B with force inversely proportional to distance squared," not "A and B exist."
3. **Map source to target.** Each source relation maps to a candidate target relation. "Attraction between center and periphery" maps to "what relation in the target connects its core to its outer parts?"
4. **Test the mapping.** Some relations transfer cleanly (productive analogy); some don't (where the analogy breaks). Both are informative.
5. **Generate target predictions.** What does the source-side relation, transferred to target, predict you'd find in target? Test those predictions empirically or evaluatively.

A second insight: **analogies generate predictions, not just descriptions.** The use of structure-mapping isn't to describe what you already know about target; it's to predict what you don't know yet by leveraging what you do know about source.

## Why Use This Thinking Tool

Three failure modes the protocol prevents:

1. **Surface-similarity analogies.** Reasoning by appearance rather than structure. "Customer journey is like a river" is structurally weak unless you specify which river-relations transfer.
2. **Single-relation mapping.** Borrowing one feature without checking whether the rest of the structure transfers. Often the analogy breaks at relation #2 or #3, but the user has already committed.
3. **Hidden source-mapping.** Many "original" ideas are unconscious analogies. Surfacing the source explicitly lets you evaluate whether the mapping is helping or limiting.

This tool's evidence base is academic (Gentner's lab, Holyoak's work) more than corporate; the structure-mapping community has produced computational models, fMRI studies, and developmental data showing children learn analogical reasoning through the surface→structural shift across early years.

## How To Use This Thinking Tool

```
|======|=================================================================================|
| Step |                                     Action                                      |
|======|=================================================================================|
|  1   | State the target problem. What do you want new ideas about?                     |
|  2   | Select a source domain. Pick one you understand richly. (Engineering, biology,  |
|      | sports, kitchens, ecosystems, music, war, theater are common high-density       |
|      | sources.)                                                                       |
|  3   | List the source's RELATIONS. Not objects. Verbs and prepositions describe       |
|      | relations; nouns describe objects.                                              |
|  4   | Build the mapping table. Source-relation → candidate Target-relation.           |
|  5   | Test each mapped relation: does it hold in the target? Mark hits and misses.    |
|  6   | For each hit, generate target-side predictions / ideas that the source-side    |
|      | structure suggests.                                                             |
|  7   | Surface where the analogy BREAKS. The breaks are diagnostic: they show where   |
|      | the target's actual structure differs from the source's. This is information,  |
|      | not a failure of the protocol.                                                  |
|======|=================================================================================|
```

> **Operational notes:** (1) **Lead with relations, not objects.** Resist the urge to map "the customer is like a fish." Instead: "the customer's attention-flow has the relational property X, like the fish's predator-avoidance pattern." (2) **Multiple sources beat a single source.** Try 3-4 source domains in sequence; each will surface different target-side relations. (3) **Domain expertise still matters.** Structure-mapping generates candidates; only target-domain expertise can evaluate whether the predictions are accurate. (4) **The breaks are not failures.** The places where the analogy stops transferring are exactly where the target has structure the source lacks — which is what you wanted to surface.

## Related Tools and Frameworks

- **Biomimicry / Cross-Domain Transfer** — source is always biology; structure-mapping is the method.
- **TRIZ** — engineering-specific cross-domain transfer with a pre-built source library (40 inventive principles).
- **Role-Based Analogy** — adjacent; structure-mapping is the cognitive science of why role-based analogy works.
- **Lateral Thinking (de Bono)** — broader provocation toolkit; structure-mapping is one disciplined form of lateral move.
