# Back of the Napkin

**One-line summary:** A practical framework for solving business problems by drawing — six question types matched to six visual-display types, plus five framing dichotomies (SQVID) — used to think through and communicate complex ideas with minimal artistic skill.

**When to reach for it:** Any business problem you can articulate but cannot quite see, whiteboard sessions where the conversation is going in circles, executive conversations where a sketch will land faster than a slide deck, and any moment when a colleague says "I don't get it" and you need to make the structure visible.

---

## Purpose Of This Thinking Tool

Dan Roam's *The Back of the Napkin* (2008) made a structural claim about visual problem-solving: **any business problem can be solved with one of six pictures**. The pictures are not stylistic choices — they are matched to the *type of question* the problem is asking. Get the matching wrong and the picture obscures rather than reveals.

The 6×6 framework:

|       Question Type         |   Visual Display     |              Use Case               |
|-----------------------------|----------------------|-------------------------------------|
| **Who / What**              | Portrait             | Identifying actors, objects, parts  |
| **How much**                | Chart (bar / pie)    | Comparing quantities                |
| **Where**                   | Map                  | Spatial / structural relationships  |
| **When**                    | Timeline             | Temporal sequence                   |
| **How**                     | Flowchart            | Process / causal chains             |
| **Why**                     | Multi-variable plot  | Trade-offs, relationships           |

The non-obvious operational insight is that **most failed business diagrams use the wrong picture for the question**. A Why-question (why is this declining?) drawn as a chart (How-much) shows the symptom but not the structure; the same question drawn as a multi-variable plot (Why) reveals which variables move together and which don't. The 6×6 match-up is the discipline that prevents this.

The second framework Roam offers is **SQVID** — five framing dichotomies that tune any sketch's emphasis:

- **S**imple ↔ Elaborate
- **Q**uality ↔ Quantity
- **V**ision ↔ Execution
- **I**ndividual ↔ Comparison
- **D**elta ↔ Status quo

Before drawing, the practitioner picks where each dial sits for this audience and this purpose. A board-level vision sketch tunes Simple, Quality, Vision, Individual, Delta. A operational status sketch tunes Elaborate, Quantity, Execution, Comparison, Status quo. Mismatched tuning produces sketches that are technically correct but tonally wrong for the audience.

The third Roam claim, repeated through all three books: **drawing skill is irrelevant**. The framework operates entirely with stick figures, simple shapes, lines, and arrows. The cognitive work is in the matching (question type → display type) and the framing (SQVID), not in the rendering.

## Why Use This Thinking Tool

Three failure modes the framework prevents:

1. **The wrong-picture trap.** Drawing a Why-question as a How-much chart, or a Where-question as a When-timeline, produces visuals that show the wrong dimension of the problem. Audiences see the picture but cannot use it. The 6×6 match-up enforces correct matching.
2. **The under-tuned sketch.** A diagram that is technically correct but emphasizes the wrong thing for its audience (too detailed for executives, too high-level for operators) fails to land. SQVID forces explicit tuning before drawing.
3. **The "I can't draw" abdication.** Practitioners who decline to use visual thinking because they "can't draw" forgo a major channel of cognitive work. The framework's accessibility (stick figures, basic shapes) removes that excuse and routinely produces useful sketches from non-artists.

For consulting and executive communication specifically, the framework is the discipline that converts a verbal stumble ("the problem is sort of, like, multi-dimensional") into a sketch that locks the conversation onto a specific structure. This is also a high-leverage live tool: drawing as you speak keeps the audience anchored, whereas pure verbal complexity drifts.

## How To Use This Thinking Tool

```
|======|=================================================================================|
| Step |                                     Action                                      |
|======|=================================================================================|
|    1 | Articulate the question. What is the audience trying to figure out? In one        |
|      | sentence: who/what, how much, where, when, how, or why?                          |
|    2 | Match question type to visual display using the 6×6 table.                       |
|    3 | Tune the SQVID dials for this audience and purpose. Simple or elaborate?         |
|      | Quality or quantity? Vision or execution? Individual or comparison? Delta or     |
|      | status-quo?                                                                      |
|    4 | Draw a small thumbnail first (1-2 inches square). Most layout problems show up   |
|      | here cheaply.                                                                    |
|    5 | Expand to full size with confidence. Use simple shapes, basic stick figures,     |
|      | clear arrows. Resist polishing.                                                  |
|    6 | Label the axes / actors / phases explicitly. Unlabeled diagrams are guessable    |
|      | only by their author.                                                            |
|    7 | Show the sketch to a stakeholder before finalizing. Ask them to read it back to  |
|      | you. Where they stumble is where the sketch is unclear.                          |
|    8 | Iterate. Most useful sketches go through 2-4 versions — not because the early    |
|      | versions were bad, but because seeing them sharpens the question.                |
|======|=================================================================================|
```

## The Actual Thinking Tool

```
THE 6×6 MATCH-UP TABLE

   |  Question  |    Display    |             What it shows                |
   |------------|---------------|------------------------------------------|
   |  Who/What  |  Portrait     | Identity, parts, components, actors      |
   |  How much  |  Chart        | Quantities, comparisons, distributions   |
   |  Where     |  Map          | Spatial / structural / network position  |
   |  When      |  Timeline     | Sequence, duration, pacing               |
   |  How       |  Flowchart    | Process, causal chain, decision tree     |
   |  Why       |  Multi-var.   | Relationships, trade-offs, mechanism     |

   Diagnostic: if you cannot decide which question type, you have not yet
   focused the question. Stop and refine the question before drawing.

THE SIX BASIC PICTURES (each is doable with stick figures and lines)

   1. PORTRAIT
        Stick figure, labeled object, or schematic of a thing
        with its parts named. Simplest possible representation.

   2. CHART
        Bars, pies, dots, simple comparison shapes. Numerical or
        categorical comparison. Always label units.

   3. MAP
        Spatial layout — geographic, organizational, network,
        process zone. Shows WHERE relationships live.

   4. TIMELINE
        Linear sequence with events placed on a temporal axis.
        Can include forks (branches) and confluences.

   5. FLOWCHART
        Boxes-and-arrows showing process, decision points, and
        causal sequences. Diamond = decision; box = action;
        circle = start/end.

   6. MULTI-VARIABLE PLOT
        Two or more dimensions plotted together, showing trade-offs
        or relationships. The 2x2 matrix is a special case.

   Rule of thumb: most consulting problems are Why-questions in disguise,
   meaning they want a multi-variable plot. But many practitioners default
   to How-much (chart) because charts are easier to make.

THE SQVID TUNING

   Before drawing, set each dial:

   S — SIMPLE  ←——————→  ELABORATE
       Audience: executives → simple. Practitioners → elaborate.

   Q — QUALITY  ←——————→  QUANTITY
       Strategic / aesthetic question → quality. Operational → quantity.

   V — VISION  ←——————→  EXECUTION
       Direction-setting → vision. Implementation → execution.

   I — INDIVIDUAL  ←——————→  COMPARISON
       Single thing in detail → individual. Across set → comparison.

   D — DELTA (CHANGE)  ←——————→  STATUS QUO
       Why act → delta. What is → status quo.

   Mismatched tuning is a common failure: a vision-level audience getting
   an execution-level diagram, or a delta question answered with a status-quo
   sketch. Pre-tune before drawing.

THE THUMBNAIL DISCIPLINE

   Always draw a 1-2 inch thumbnail first. Three reasons:

   1. Layout problems are visible at thumbnail scale and are cheap
      to fix there. They become expensive at full scale.
   2. The thumbnail forces decisions about what fits — preventing the
      "I'll add detail later" trap that produces overcrowded sketches.
   3. Multiple thumbnails (4-6 on a page) let you compare layouts
      before committing.

   Roam: "If you can't draw it small, you don't yet understand it."

THE LIVE-WHITEBOARD APPLICATION

   When drawing in front of an audience:

   1. Speak as you draw. The drawing anchors attention.
   2. Build incrementally — one element at a time — so the audience
      can follow.
   3. Pause to let the audience point at things. The pointing is
      part of their thinking.
   4. Don't erase early elements. Cross out, mark, annotate — but
      preserve the trail. The trail is part of the meaning.
   5. After: photograph the whiteboard. The photo is the artifact;
      transcription destroys the spatial information.

WHAT TO PRACTICE FIRST

   1. The six basic pictures, drawn from memory, in 60 seconds each.
   2. The 6×6 matching: pick three real business questions and assign
      each to its display type.
   3. The SQVID dials: take a finished sketch and re-tune one dial.
      How does it change?
   4. Live drawing: in your next 1:1 or stand-up, sketch one concept
      while talking. Don't pre-draw; build live.
```

> **Operational notes:** Four disciplines. (1) Question-type diagnosis is the highest-leverage move. Most failed diagrams fail because they answer the wrong question, not because they are poorly drawn. The 6×6 match-up forces explicit alignment between the question type and the display type. (2) SQVID tuning is the second-most-leveraged move. A correctly typed sketch with mis-tuned framing still misfires — too elaborate for executives, too vision-y for operators. Set the dials before drawing. (3) Drawing skill is genuinely irrelevant. Stick figures, labeled boxes, simple arrows — the framework operates entirely with these. The most common reason professionals avoid the practice ("I can't draw") is a non-issue once they try, and the cognitive payoff is large. (4) Live drawing in conversation is a high-leverage variant — keep it small, build incrementally, and photograph the whiteboard afterward. The drawing process itself anchors attention more than any prepared visual; the audience is implicated in the construction rather than presented with a finished thing to evaluate.
