# Ishikawa Fishbone Diagram

**One-line summary:** Causal categorization diagram (Kaoru Ishikawa, 1968) organizing potential root causes — typically the 6Ms (Manpower, Method, Machine, Material, Measurement, Mother Nature) — into branches feeding a defect or event.

**When to reach for it:** Root-cause analysis for a quality defect, process failure, or recurring incident. Used in manufacturing, healthcare quality improvement, software incident review, and service-design troubleshooting.

## Purpose

Root causes are usually invisible because we think about effects from a single perspective. The fishbone forces the analyst to consider causes across multiple categorical axes simultaneously — Method, Material, Machine, etc. — preventing premature closure on the first plausible explanation. The visual structure also makes the diagnosis collaborative: each branch can be assigned to a different expert.

## How To Use

1. **State the effect.** Write the problem/defect at the "head" of the fishbone.
2. **Draw major bones** for each cause category. (Manufacturing default: 6Ms. Service default: 4Ps — People, Processes, Policies, Plants. Customize per context.)
3. **For each category, brainstorm causes.** Add them as smaller bones off each major bone.
4. **Iterate with 5 Whys.** For each candidate cause, ask why it occurs — sub-causes go on smaller bones.
5. **Prioritize.** Which causes are most likely? Most testable? Test top candidates with data.
