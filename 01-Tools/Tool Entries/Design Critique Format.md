# Design Critique Format

**One-line summary:** A structured peer-review protocol — presenter states intent and questions, reviewers offer description → diagnosis → suggestion in separated turns — that protects design work-in-progress from feedback dysfunctions (vague compliments, ego-fight, project-derailment) and produces actionable critique.

**When to reach for it:** Design work that needs peer input but where loose feedback rounds have produced confusion or politeness rather than useful critique; teams establishing a review culture; teaching contexts where structured critique builds reviewer skill; cross-functional design reviews where reviewers don't share an aesthetic vocabulary.

---

## Purpose Of This Thinking Tool

The art-school desk crit and architectural studio review trace back to Bauhaus pedagogy in the 1920s. The form: an apprentice presents work-in-progress; the master (later: peers) walks around, asks questions, points out problems and possibilities. The discipline is collective reasoning *about the artifact*, not consensus-building or evaluation-of-the-maker.

Modern systematization across design fields converges on a similar protocol:

1. **Presenter framing.** The maker states: the brief, the intent, the constraints, and *specific questions* they want feedback on. Without specific questions, critique drifts.
2. **Reviewer description (no judgment).** Each reviewer first describes what they see in the artifact — concretely, before any evaluative move. This forces attention to the actual work, not a remembered version.
3. **Reviewer diagnosis.** What's working? What isn't? Specific to the questions the presenter asked.
4. **Reviewer suggestion.** Concrete moves the presenter could try. Optional — sometimes diagnosis is enough.
5. **Presenter receives without defending.** The presenter doesn't argue. May ask clarifying questions but doesn't justify decisions. Time-bounded.
6. **Presenter integrates.** After all reviewers, the presenter says what they're taking and what they're not.

The non-obvious operational claim: **separating the turns prevents the critique from collapsing.** Without separation, "I see X" gets mixed with "X is bad" gets mixed with "you should do Y" — and the presenter spends the session defending rather than receiving. Separation forces reviewers to ground their critique in description before evaluation.

A second insight: **the questions the presenter asks shape the critique.** "What do you think?" produces drift; "Is the navigation hierarchy clear at first glance?" produces targeted critique. The protocol forces the presenter to know what they need.

## Why Use This Thinking Tool

Three failure modes the format prevents:

1. **Vague-compliment feedback.** "I like it" / "It's good" — useless. The protocol forces description before evaluation.
2. **Project-derailment.** Reviewers re-framing the brief instead of responding to the work. The presenter's intent-and-questions step grounds the session.
3. **Maker-defending mode.** Presenter argues every point; nothing absorbed. The receiving-without-defending discipline prevents.

## How To Use This Thinking Tool

```
|======|=================================================================================|
| Step |                                     Action                                      |
|======|=================================================================================|
|  1   | Set the container: time, roles, ground rules. 30-60 min typical.                |
|  2   | Presenter shows the work, states brief + intent + constraints + 2-3 specific  |
|      | questions they want feedback on.                                                |
|  3   | Reviewers take turns. Each round: ONE reviewer offers description (concrete,  |
|      | non-judgmental) → diagnosis (relative to presenter's questions) → suggestion. |
|      | Other reviewers don't interrupt.                                                |
|  4   | Presenter listens. May ask clarifying ("did you mean X or Y?") but does not   |
|      | defend or justify. Notes-taking encouraged.                                     |
|  5   | After all reviewers: presenter speaks. "Here's what I'm taking, here's what  |
|      | I'm not, here's what I want to think about more."                              |
|  6   | Optional: a final round where reviewers can riff on each other's points.      |
|======|=================================================================================|
```

## The Actual Thinking Tool

```
Design Critique Session Template

PRESENTER:        __________________
REVIEWERS:        __________________
TIME:             ___ min

PRESENTER FRAMING:
   Brief / problem being solved:
   _________________________________________________

   Intent / what I'm trying to achieve:
   _________________________________________________

   Constraints (timeline, budget, technical, etc.):
   _________________________________________________

   2-3 specific questions for critique:
   1. _____________________________________________
   2. _____________________________________________
   3. _____________________________________________

REVIEWER ROUNDS (one at a time):

   Reviewer 1: ________
     Description: _______________________________
     Diagnosis:   _______________________________
     Suggestion:  _______________________________

   Reviewer 2: ________
     Description: _______________________________
     Diagnosis:   _______________________________
     Suggestion:  _______________________________

   Reviewer 3: ________
     Description: _______________________________
     Diagnosis:   _______________________________
     Suggestion:  _______________________________

PRESENTER INTEGRATION:
   Taking:        _____________________________________
   Not taking:    _____________________________________
   Need to think about: _______________________________

OPTIONAL FINAL RIFF:
   _________________________________________________

NEXT REVIEW:    _______ (date/milestone)
```

> **Operational notes:** (1) **Description before judgment is the hardest discipline for new reviewers.** Most jump to evaluation immediately. Practice and gentle coaching are required. (2) **Two-question framings work better than open ones.** "What do you think?" produces drift; specific questions produce critique. (3) **The format is for work-in-progress, not finished work.** Once shipped, the format is different (post-mortem). (4) **Cross-functional crits need shared vocabulary.** Engineers and designers reviewing each other's work need brief vocabulary alignment first. (5) **The maker's "not taking" is legitimate.** The protocol's purpose is informing the maker, not over-ruling them. Final decisions stay with the maker.
