# Tool Sequencing Playbooks

**One-line summary:** A meta-discipline that documents pre-defined sequences of thinking tools applied to recurring problem types — each playbook an ordered set of tools with handoffs — recognizing that tools rarely work alone and that sequencing matters as much as individual tool choice.

**When to reach for it:** Recurring problem types where multiple tools are typically needed (strategic pivot, innovation initiative, organizational change, market entry); team training (transmitting tacit consulting wisdom about tool composition); facilitator design for workshops; scaling expertise across less-experienced practitioners; and any context where the order and combination of tools matters as much as which tools to use.

---

## Purpose Of This Thinking Tool

**Tool sequencing playbooks** document tool combinations for recurring problems. The structure:

1. **Identify recurring problem type** (strategic pivot, innovation, organizational change, etc.).
2. **Map the typical workflow** — which tools, in which order, with what handoffs.
3. **Document the playbook** — for each tool: when to apply, what it produces, how it feeds the next tool.
4. **Apply** the playbook for instances of the problem type.
5. **Refine** based on experience — playbooks evolve.

The non-obvious operational insight is that **individual tool excellence isn't enough; tools combine into workflows.** A well-applied SWOT alone is incomplete; SWOT followed by Wardley Maps followed by Pre-mortem followed by Decision-context matching produces a more complete strategic answer. The composition is what experienced consultants and strategic teams have internalized; novices apply tools individually and miss the combinatorial leverage.

A second insight: **playbooks transmit tacit wisdom.** Senior consultants know which tools fit recurring engagements; juniors don't. Documenting playbooks transmits the wisdom; it scales expertise.

A third insight: **playbooks are starting points, not rigid scripts.** Each engagement / situation may require deviations. The playbook is the default sequence; deviations are explicit choices, not abandonment.

A fourth insight: **the framework integrates with Cynefin-based selection.** First diagnose domain; then select playbook (which itself contains tool selection); then apply. The two meta-tools work together at different layers.

## Why Use This Thinking Tool

Three failure modes the framework prevents:

1. **The "individual tools, no composition" gap.** Tools applied separately miss the leverage of sequenced application.
2. **The "wrong order" failure.** Right tools, wrong sequence (e.g., decision before analysis); produces wrong answers.
3. **The "novice can't compose" issue.** Inexperienced practitioners don't know which tools combine well; reinvent or fumble.

For consulting firms, internal strategy teams, organizational training leads, facilitators, and anyone responsible for replicable application of multi-tool workflows, sequencing playbooks are foundational.

## How To Use This Thinking Tool

```
|======|=================================================================================|
| Step |                                     Action                                      |
|======|=================================================================================|
|    1 | Identify recurring problem types in your practice. Strategic pivots, M&A,      |
|      | innovation, organizational change, etc.                                          |
|    2 | For each, document the typical tool sequence. What's the first tool? What     |
|      | comes after? Why?                                                                  |
|    3 | Document handoffs. What does each tool produce that feeds the next?            |
|    4 | Note when to deviate. Some situations call for variations.                      |
|    5 | Test the playbook. Apply it to a real instance; see if it produces useful      |
|      | output.                                                                            |
|    6 | Refine based on experience. Playbooks evolve.                                    |
|    7 | Teach the playbook. Transmit to others; share across team.                      |
|    8 | Build a library of playbooks for the recurring problems you see.               |
|======|=================================================================================|
```

## The Actual Thinking Tool

```
THE PLAYBOOK STRUCTURE

   Problem type: __________________

   Tool 1: ____________________
       When to apply: _________
       Produces: ______________

   ↓ (handoff)

   Tool 2: ____________________
       When to apply: _________
       Produces: ______________

   ↓ (handoff)

   ...

   Tool N: ____________________
       Final synthesis / decision

   Handoffs document what each tool produces that the
   next tool consumes. Without explicit handoffs,
   tools sit alongside each other rather than
   composing.

THE WORKED EXAMPLE — STRATEGIC PIVOT PLAYBOOK

   Problem type: company considering major strategic
   pivot in response to disruption.

   Step 1: Cynefin diagnosis
       Tool: Cynefin
       When: at the start, to understand domain.
       Produces: domain (likely Complex if facing
       disruption).

   Step 2: External-environment analysis
       Tool: Porter's Five Forces + PESTLE
       When: after Cynefin (need to understand
       external pressures).
       Produces: industry-attractiveness analysis,
       trend signals.

   Step 3: Internal capability assessment
       Tool: VRIO (or Resource-Based View)
       When: paired with external analysis.
       Produces: which strengths are sustainable
       advantages.

   Step 4: Customer-job analysis
       Tool: Jobs-to-Be-Done
       When: after external + internal.
       Produces: what jobs customers actually hire for;
       reveal new positioning.

   Step 5: Wardley map
       Tool: Wardley Maps
       When: integrate above into evolutionary view.
       Produces: where competitive advantage currently
       sits; where it's evolving toward.

   Step 6: Strategic options generation
       Tool: SCAMPER + Role-Based Analogy
       When: with the analysis in hand.
       Produces: list of strategic options.

   Step 7: Option evaluation
       Tool: Decision-context matching + Real Options
       Analysis
       When: option list ready.
       Produces: prioritized options + recommendation.

   Step 8: Pre-mortem
       Tool: Pre-Mortem
       When: before commit.
       Produces: risks + mitigations.

   Step 9: Implementation plan
       Tool: Reverse-engineered milestones
       When: option chosen.
       Produces: executable plan with milestones.

   This is a 9-tool playbook. Senior consultants
   compose it intuitively; juniors benefit from the
   explicit documentation.

THE WORKED EXAMPLE — INNOVATION PLAYBOOK

   Problem type: identifying and developing a new
   product idea.

   Step 1: Customer-job analysis
       Tool: Jobs-to-Be-Done
       Produces: jobs customers struggle with.

   Step 2: Empathy mapping
       Tool: Empathy Maps
       Produces: customer-experience layer.

   Step 3: Idea generation
       Tool: SCAMPER + Role-based analogy + Biomimicry
       Produces: candidate solutions.

   Step 4: Concept evaluation
       Tool: Strategy Canvas (Blue Ocean) + JTBD fit
       Produces: which ideas worth pursuing.

   Step 5: Pre-mortem
       Tool: Pre-Mortem
       Produces: failure modes to address.

   Step 6: Pilot design
       Tool: Real Options Analysis (small experiment
       with optionality)
       Produces: pilot plan.

   Step 7: Pilot execution
       Tool: Stock-and-flow / scaling considerations
       Produces: pilot results.

   Step 8: Roll-out / abandon decision
       Tool: Decision-context matching
       Produces: scale, modify, or kill decision.

   The playbook covers idea-to-decision systematically.

THE PLAYBOOK-DEVIATION DISCIPLINE

   Playbooks are starting points, not scripts.

   Deviation reasons:
       Specific situation reveals different domain
       Tool 3 already done in different context
       Time pressure forces shortcut
       Tool's typical input not available; substitute

   Discipline:
       Note deviation explicitly
       Document why
       Refine playbook based on patterns of deviation
       (if many engagements deviate same way, the
       playbook is wrong)

THE PLAYBOOK-LIBRARY BUILDING

   Build a library:

   Strategic pivot playbook
   Innovation playbook
   M&A playbook
   Organizational change playbook
   Crisis response playbook
   Annual planning playbook
   Hiring decision playbook
   Investment decision playbook

   Each documented; refined over time; taught.

   The library is firm-level capability that scales
   beyond individual senior consultants' tacit
   knowledge.

THE COMMON FAILURE MODES

   1. NO PLAYBOOKS
        Each engagement re-invents tool selection.
        Recovery: document playbooks for recurring
        types.

   2. UNDOCUMENTED HANDOFFS
        Playbook lists tools but doesn't show how
        they connect. Recovery: explicit "what each
        produces, how next consumes."

   3. RIGID ADHERENCE
        Following playbook regardless of situation.
        Recovery: deviations as explicit choices.

   4. PLAYBOOK NEVER REFINED
        First version preserved indefinitely.
        Recovery: periodic refinement.

   5. NOT TAUGHT
        Senior knows playbook; juniors don't.
        Recovery: explicit teaching; pair work.

   6. WRONG GRANULARITY
        Playbook too detailed (becomes script) or too
        vague (no guidance). Recovery: middle ground;
        tool-level steps with judgment within.

   7. NO DEVIATION TRACKING
        Deviations not noted; playbook not refined.
        Recovery: track deviations as data.

THE OPERATIONAL TEMPLATE

   Problem type: ______________________________________

   Playbook tool sequence:
       Step 1: __________________________________
           Tool: ______________________________
           Produces: ___________________________
       Step 2: __________________________________
           Tool: ______________________________
           Produces: ___________________________

           Tool: ______________________________

       Step 1 → Step 2: __________________________
```

> **Operational notes:** Four disciplines. (1) Document the sequence, not just the tools. The order and handoffs are where the leverage lives; without them, the playbook is just a list. (2) Match playbook to problem type. Different recurring problems need different playbooks; one playbook for all situations is the failure mode. (3) Allow deviations. Playbooks are starting points; specific situations may require variations. The discipline is making deviations explicit choices, not unconscious drift. (4) Build a library. Individual playbooks have value; a library of playbooks is firm-level capability. The library scales beyond senior practitioners' tacit knowledge.
