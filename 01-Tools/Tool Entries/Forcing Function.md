# Forcing Function

**One-line summary:** Structural arrangements that make a desired action unavoidable or an undesired action impossible — relying on architecture rather than willpower.

**When to reach for it:** Reliability-critical workflows (medical safety, deployment processes), habit formation that has failed under intent alone, organizational behavior change that needs to be sustained without continuous attention.

## Purpose

Intent + willpower is unreliable; environmental architecture is durable. Forcing functions encode the desired behavior into the structure of how work happens, so the desired outcome doesn't depend on remembering or being motivated. Examples: car keys that won't start in reverse with the door open; deployment pipelines that require code review before merge; calendar autoblocks for protected time. The discipline is identifying where willpower keeps failing and replacing it with structure.

## How To Use

1) Identify the behavior that should be reliable but isn't. 2) Map why it fails (forgetting, motivation, social pressure). 3) Design an environmental change that makes the desired path easier than the undesired path — ideally, only the desired path possible. 4) Test the function actually forces. 5) Iterate based on observed circumvention.
