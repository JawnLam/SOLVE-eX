# Map-Territory Distinction

**One-line summary:** The map is not the territory — every model, abstraction, or description is incomplete and may differ from the underlying reality.

**When to reach for it:** Whenever a model, dashboard, KPI, or framework starts being treated as the reality it represents; when arguments turn on definitions rather than observations.

## Purpose

Korzybski's general-semantics insight is that conceptual representations are necessarily lossy. The hazard is operating on the map (the model, the chart, the spec) as if it were the territory (actual reality), which leads to optimizing the model rather than the underlying phenomenon. The stance is recurring re-grounding: walk the floor, read the raw data, talk to the user, watch the system — and keep asking where the map diverges from the territory.

## How To Use

1) For each model in active use, name three places where it abstracts away detail. 2) For each, ask: when might that abstraction matter? 3) Build periodic ground-truth practices (site visits, raw-log review, user interviews). 4) When the map and territory disagree, prefer the territory and update the map.
