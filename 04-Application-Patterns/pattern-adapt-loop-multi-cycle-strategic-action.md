# Pattern — The ADAPT Loop: Multi-Cycle Strategic Action

## What this pattern is

An integrative session-design lens that organizes the use of twelve
ADAPT-Loop tool entries (eight mandatory + four optional, all in
`{ROOT}/01-Tools/Tool Entries/`) and the supporting field manual
(`{ROOT}/10-Reference/ADAPT-Loop-Field-Manual.pdf`) into a coherent
diagnostic-and-deliberation pass on situations involving strategic
action under multi-actor political conditions. It is not a per-tool
interaction pattern (those live in the `pattern-{form-slug}.md` files
of this directory) — it is the meta-pattern that determines when the
ADAPT-family tools fit a session, which combinations of them fit a
given case, and how the field manual's four views map onto the
diagnostic loop's per-turn work.

The framework's central framing — load-bearing for everything below —
is the dissertation's Chapter 6 observation (Lam 2020 p. 226):

> "None of them [the participants] delineated their activities to this
> level of granularity. While all the documented interactions did
> indeed track in accordance with the workflow of the model, the
> participants did not exhibit full awareness or intentionality to
> crafting a detailed roadmap of any of their interactions."

The ADAPT Loop is a *post-hoc explanatory framework that becomes a
prescriptive lens when consciously applied.* The framework's value is
making deliberate practice possible for situations where intuition is
insufficient — high stakes, novel context, time pressure that exceeds
intuitive throughput, post-hoc audit of a result that surprised the
actor. The application pattern is therefore a lens-deployment
discipline, not a step-by-step prescription. Sessions that read ADAPT
as a recipe lose the framework's most important property — that it
makes the actor's mistakes legible to them afterward, which is what
permits the next cycle to be better than the last (Field Manual p. 40).

## The four views as entry points

The field manual presents the ADAPT Loop through four progressively
zoomed views (Field Manual pp. 5-19). The views are not pedagogical
layers stacked on a master diagram — they are alternative entry points
into the same model. Different sessions enter different views; the
choice of entry view is part of the diagnostic.

### View 1 — The whole loop (Field Manual ch. 3, pp. 9-10)

The five ADAPT beats (Agenda → Decide → Act → Perceive → Track) across
two clearly labeled zones — planning (reversible) and consequence
(irreversible). This is the map; the next three views are the
territory. Useful when a session needs orientation: which beat is the
user actually in right now? The field manual names four common stuck
states corresponding to the beats — stuck in Agenda (have an agenda
but no clear objective), stuck at the Decide gate (cannot sustain
action; each attempt depletes resources), stuck deciding (too many
options without scoring discipline), stuck in Perceive / Track (cannot
tell whether the move worked).

**Enter View 1 when:** The user's situation is intractable and the
diagnostic question is which beat they are stuck in. The field manual
note is load-bearing here (p. 10): *"distinguishing 'I am stuck
deciding' from 'I am stuck at the capability gate' is itself a
strategic move; the two produce opposite behaviors when treated the
same way."*

### View 2 — Forming the aim (Field Manual ch. 4, pp. 11-13)

The planning funnel from Actor through Agenda → Interest → Objective →
Goal → Target. The funnel runs only one direction; the funnel's
discipline is that an actor's behavior surprises usually have their
explanation above the level of the behavior. Operationalized by the
tool `Actor-Agenda Decomposition`.

**Enter View 2 when:** The user describes a vague want that resists
concrete planning ("more influence," "be taken seriously," "win this
account"), when a counterparty's behavior is producing surprises the
user's analysis cannot explain, when a stakeholder conversation keeps
shifting register without resolving.

### View 3 — The decision (Field Manual ch. 5, pp. 14-16)

The capability gate plus the decision matrix. The decision matrix
scores each option on Preferred Position (PP) AND Adverse Alternative
(AA), each on Benefit + Cost + Utility = at least four components.
Reading discipline: compare the U(PP) / U(AA) pair across options,
don't pick highest U(PP) alone. Operationalized by
`Required-Resource Check`, `Decision Matrix Construction`,
`Bet vs Workhorse Discrimination`, and the optional
`9-Resource Portfolio Diagnostic` and `Disciplined Hold` (when the
gate returns No).

**Enter View 3 when:** The user has a target and is at the threshold
of committing to a move; when option selection has emotional weight
and the matrix's discipline would corrective; when "go big" reflex is
competing with workhorse reasoning; when the resource question is
unsettled.

### View 4 — Act, Perceive, Track (Field Manual ch. 6, pp. 17-19)

Action plays out through its components; produces actual effect;
actual utility is measured against target; the perception gap (Actual
− Perceived) is the framework's quiet but central error term;
observation and outcome feed the resource loop and the learning loop
into the next cycle. Operationalized by `Perception and Actual Effect
Gap Audit`, the optional `Calibration Gap Read`, and the multi-cycle
stance `Iterated Loop Compounding`.

**Enter View 4 when:** The user has already taken an action and
reports either a result or a surprise; when the question is whether
the move worked and how the user would know; when prior cycles have
left unexamined perception gaps that may now be compounding.

## Multi-cycle architectural patterns

The framework's most consequential operational insights are patterns
that emerge across cycles — patterns invisible from any single-cycle
view. Each pattern below maps to specific tool entries and to
case-study extracts from the field manual.

### Pattern 1 — Nested sub-cycles on resource-check failure

When the capability gate returns No, the framework's discipline is to
open a sub-cycle to procure the missing resource, not to plow ahead or
abandon. The sub-cycle is a full ADAPT cycle: own actor (the same),
own target (the party that controls the missing resource), own
decision matrix. Sub-cycles can nest three deep — Sarah → Margaret
required Sarah → Beth as sub-cycle, which required further sub-cycles
(Lam 2020 Table 14, pp. 195-196). Rusty's case opens three sub-cycles
within the Rusty → Todd umbrella (dissertation Tables 17-21,
pp. 207-216).

**Operationalized by:** `Required-Resource Check` (the gate),
`Nested Sub-Cycle Discipline` (the cycle-stack discipline),
`Actor-Agenda Decomposition` (the funnel run on the sub-cycle's
target), `9-Resource Portfolio Diagnostic` (naming the missing
resource precisely).

**Case-study extract:** Cresterly Cycle 2 (Field Manual ch. 7, p. 23)
— Diana Reyes's gate returns No on a formal restructuring proposal;
she opens a sub-cycle whose interest is the CFO's active sponsorship,
which closes six months later and makes Cycle 3 decisive (p. 24).

### Pattern 2 — Multi-PP hierarchy

Actors can have ranked preferences within preferred positions, not
just preferred vs. adverse. Rusty has P1 = "Todd leaves voluntarily"
preferred over P2 = "Rusty fires Todd," both preferred over X = "Todd
stays" (dissertation Tables 17-21). Each preferred position has its
own resource cost and adverse-side spillover; collapsing them into a
single PP throws away the discrimination the actor most needs to make.

**Operationalized by:** `Decision Matrix Construction` (the multi-PP
sub-discipline lives inside this tool's `How To Use` step 3-4).

### Pattern 3 — Mid-cycle interest pivot (abductive reformulation)

An actor enters an interaction cycle with one interest; mid-execution
reveals that a different interest serves the agenda better; the actor
pivots. Operational analog of GTM's abductive reasoning. The pivot
updates the interest, not the agenda; the cycle remains live but
reformulates what it is for. Anti-sunk-cost-fallacy at the
interaction-cycle level.

**Operationalized by:** `Mid-Cycle Interest Pivot` (optional tool).

**Case-study extract:** Sarah → Srini saturation test (Lam 2020 Table
14, pp. 195-196) — Sarah enters under "gather information about
Srini" and pivots mid-conversation to "convince Srini to step out of
the competition" when Srini's career-stage preference makes
elimination feasible.

### Pattern 4 — Calibration gap on consequence reach

The intended outcome and the actual outcome differ in magnitude. The
gap is usually not random — it is most often explained by a third
party running their own ADAPT cycle overlaid on the actor's. The
Charles case (Lam 2020 ch. 5, pp. 108-109): four managers planned a
12-month transfer-and-demote; CFO fired Harry in 4 weeks. The gap was
not noise; it was the precise output of the CFO's overlay matrix.

**Operationalized by:** `Calibration Gap Read` (optional tool),
`Cross-Actor Matrix Reading` (the perspective-shift lens that runs the
ADAPT funnel on the overlay actor), `Perception and Actual Effect Gap
Audit` (the prior diagnostic distinguishing Expected / Actual /
Perceived).

**Case-study extract:** Cresterly Cycle 3 Lessons (Field Manual ch. 7,
p. 25) — *"Apparent randomness in outcomes is usually another actor's
matrix. What looked, from a single-actor perspective, like
uncontrollable reality (joint governance, the leash, the review),
was, in the two-actor view, the precise output of Vale's matrix."*

### Pattern 5 — Iterated loop compounding

Strategic life is the iterated running of cycles. Each cycle's outcome
feeds the next cycle's resource portfolio (the resource loop) and
reshapes the actor's interests (the learning loop). Both loops are
slow and easily corrupted. The recursive prescription (Lam 2020 p. 226):
*Control the resources that facilitate the ability and opportunity to
control more resources.* Politically useful resources are those that
compound — Credibility, Attributes, Information, Access, Tribe (see
`9-Resource Portfolio Diagnostic` for the 9-type taxonomy).

**Operationalized by:** `Iterated Loop Compounding` (optional stance).

**Case-study extract:** Talvyn Eighteen-months-later passage (Field
Manual ch. 9, pp. 36-37) — Jia Yarrow's three cycles compound across
eighteen months; perception gap narrows; agenda is served by
trajectory, not by any single cycle.

## When to invoke ADAPT in a SOLVE eX session

The framework fits sessions where the strategic situation involves
*another actor's selection* — a decision in which the user's outcome
depends on what some other party will choose. Specifically, invoke
ADAPT when:

1. **The user's outcome is gated by another actor's decision.** The
   user can prepare, position, propose, and observe — but a specific
   counterparty (or coalition) makes the actual call. This is the
   framework's home territory.
2. **The capability-gate question is unsettled.** The user is at the
   threshold of action but the resource position has not been audited
   explicitly. Trigger: `Required-Resource Check` + `9-Resource
   Portfolio Diagnostic`.
3. **The user reports a result that differs from expectation.** Either
   direction — better than expected (often a third-party overlay; run
   `Calibration Gap Read` + `Cross-Actor Matrix Reading`) or worse
   than expected (likely a perception gap; run `Perception and Actual
   Effect Gap Audit`).
4. **The user is about to take action under pressure to "do
   something."** Trigger: `Disciplined Hold` as the stance to test
   before committing.
5. **The user is returning for a second or third session on a related
   strategic effort.** Trigger: `Iterated Loop Compounding` as the
   multi-session lens.
6. **The session is debriefing a recent surprise — favorable or
   unfavorable — in a political situation.** Trigger:
   `Perception and Actual Effect Gap Audit` followed by
   `Calibration Gap Read` if magnitude is the surprise.

## When NOT to invoke ADAPT

The framework's home territory is decisions involving other human
actors. ADAPT is the wrong lens when:

1. **The relevant other parties are inanimate.** Markets, weather,
   physical systems, codebases without humans behind them. These can
   be analyzed with other tools (`Five Whys`, `Theory of Constraints`,
   `Real Options Analysis`, scenario planning) but they do not run
   ADAPT cycles; the framework's cross-actor reading does not apply.
2. **The decision is purely technical.** When the question is "which
   architecture pattern fits," "which algorithm minimizes cost," or
   "which statistical method applies," the human-political layer is
   not load-bearing. Use the technical-decision tools directly.
3. **The user's situation is at the personal-existential layer.**
   Questions of values, identity, or meaning are not ADAPT shape. The
   `Counselor` persona's tools (`Eulogy Exercise`, `Ikigai Diagram`,
   `ACT Values Clarification`) are the correct register.
4. **The framework would manufacture a political reading where none
   exists.** Over-applying ADAPT to a situation that is genuinely
   non-political produces a strategic analysis that mismaps the
   situation and loses the user's trust. The fit test: is there a
   specific other actor whose selection the user's outcome depends
   on? If no, ADAPT is the wrong lens.

## Tool composition within an ADAPT-themed session

The twelve ADAPT tools chain together along the framework's beats.
Common compositions (informational; the diagnostic loop's per-turn
work selects from this menu based on session state):

- **Planning-zone work (Phases 1-5):**
  `Actor-Agenda Decomposition` (View 2)
  → `9-Resource Portfolio Diagnostic` + `Required-Resource Check` (View 3 gate)
  → `Decision Matrix Construction` + `Bet vs Workhorse Discrimination` (View 3 matrix)
  → optional `Disciplined Hold` if gate returns No
  → optional `Nested Sub-Cycle Discipline` if sub-cycle opens.
- **Consequence-zone work (Phase 6):**
  `Perception and Actual Effect Gap Audit` (View 4)
  → optional `Calibration Gap Read` if outcome magnitude surprises
  → optional `Cross-Actor Matrix Reading` to model the overlay actor.
- **Across-cycle work (multi-session):**
  `Iterated Loop Compounding` as the framing stance
  → optional `Mid-Cycle Interest Pivot` when mid-execution observation
  reveals a different interest serves the agenda.

## Notes on the pattern's structural position

This is the corpus's first *integrative session-design* application
pattern — one that organizes the use of multiple tools toward a
specific framework's discipline, rather than describing how a single
`tt_Form` value is enacted in conversation. The form-mapping patterns
(`pattern-matrix.md`, `pattern-sequenced-workflow.md`,
`pattern-mental-model.md`, etc.) describe *how to apply one tool*. This
pattern describes *which tools to apply, in what combinations, in what
situations* under a specific theoretical framework. Future
integrative-session-design patterns for other frameworks (when added)
can follow the structure here: Framework overview → entry-point views
→ multi-cycle architectural patterns → when-to-invoke / when-not →
tool composition → glossary cross-reference.

Form-mapping patterns and integrative patterns coexist; each tool entry's
`tt_Form` value still maps to a per-form pattern in this directory for
the *how the tool is enacted conversationally* question. The
integrative pattern adds the *which tools and when* question for the
ADAPT-family specifically.
